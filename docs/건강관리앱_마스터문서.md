# 종합 건강관리 앱 — 설계·요구사항 마스터 문서
**(가칭) 헬씨플랜 | 작성 2026.8.13 · 개정 2026.8.13(제2판) | 발주자: 송정호**

이 문서는 앱 완성까지의 기준이 되는 문서입니다. 개발 중 방향이 흔들릴 때, 또는 Claude에게 작업을 지시할 때 이 문서를 첨부하면 처음의 의도대로 개발이 이어집니다.

---

## 1. 개발 배경과 의도 (발주자의 뜻)

1. 식단, 운동, 생활습관이 각각 다른 앱에 흩어져 있어 불편하다. **하나의 앱에서 종합 관리**하고 싶다.
2. 나(발주자)는 **운동·영양 분야 지식이 없다.** 어떤 운동을 해야 하는지, 어떻게 하는지 모른다. 따라서 이 앱은 **아무것도 모르는 사람이 그대로 따라만 하면 되는 앱**이어야 한다.
3. 운동은 자세(방법)가 중요하다고 들었다. **모든 운동에 방법 설명이 함께 제공**되어야 한다. 잘못된 자세로 다치는 일이 없어야 한다.
4. 목표는 사람마다 다르다. **체중 유지·증량·감량** 목표에 따라 식단과 운동이 자동으로 맞춰져야 한다.
5. 식단은 **일 단위 기록 + 주 단위 계획 + 월 단위 리포트**로 관리한다.
6. 야외 운동은 **트래킹 앱처럼 지도에 경로가 기록**되어야 하고, 실내 운동(홈트)도 지원해야 한다.
7. **가족과 식단을 공유**하되, 체중 같은 민감한 정보는 보이지 않게 하여 **서로 불편하지 않아야** 한다.
8. 개발 방식은 웹앱(PWA)으로 하되, 필요 시 앱스토어 등록이 가능한 방식으로 확장한다.
9. **내가 지금 하고 있는 노력이 어떤 효과가 있는지 실시간으로 보여야 한다.** 운동을 마친 뒤에야 결과가 나오면, 힘든 도중에는 아무 보상이 없어 중간에 그만두게 된다. 운동을 바꾸거나 따라 하는 그 순간에 효과가 눈에 보여야 계속하게 된다.

## 2. 핵심 설계 원칙: "몰라도 되는 앱"

발주자가 운동 지식이 없다는 점이 이 앱의 가장 중요한 설계 조건입니다. 이를 위해 앱은 다음 4가지를 지킵니다.

**원칙 1 — 앱이 정해주되, 대안 선택이 항상 가능하다**
사용자가 운동을 고르는 것이 아니라, 온보딩 설문(목표·체력 수준·가능 시간·장소) 결과로 **앱이 오늘의 운동을 자동 배정**한다. 사용자는 "시작" 버튼만 누르면 된다.
단, 배정된 운동을 할 수 없는 경우(무릎 통증, 공간·장비 없음, 층간소음, 단순히 싫음 등)를 위해 **모든 운동 옆에 "다른 운동으로 바꾸기" 버튼**을 둔다. 누르면 같은 부위·같은 효과의 대안 운동 2~3개를 즉시 제시하고, 선택하면 루틴에 반영된다. 자주 바꾸는 운동은 앱이 학습하여 다음 배정에서 제외한다. (예: 점프 스쿼트 → 층간소음 걱정 시 일반 스쿼트/월싯으로 교체)

**원칙 2 — 모든 운동에 4단 설명이 붙는다**
운동 라이브러리의 모든 운동은 아래 형식을 반드시 갖춘다.
- ① **동작 그림/애니메이션**: 시작 자세 → 동작 → 복귀 (일러스트 또는 GIF)
- ② **단계별 방법**: "1. 발을 어깨너비로 벌린다 → 2. ..." 3~6단계 텍스트
- ③ **흔한 실수와 부상 주의**: "무릎이 발끝보다 앞으로 나가면 안 됩니다" 등
- ④ **호흡법과 난이도 조절**: 힘들면 쉬운 변형, 쉬우면 어려운 변형 안내

**원칙 3 — 운동 중에는 앱이 코치가 된다**
운동 실행 화면에서 현재 운동의 그림+핵심 자세 문구를 크게 표시하고, 타이머·세트 카운트·휴식 알림을 음성/진동으로 안내한다. 사용자는 화면만 따라 하면 된다.

**원칙 4 — 노력이 즉시 보이게 한다 (계속하게 만드는 장치)**
초보자가 실패하는 이유는 방법을 몰라서가 아니라 **중간에 그만두기 때문**이다. 힘든 것은 지금인데 보상이 나중이면 버티지 못한다. 따라서 노력의 효과가 **그 순간에** 보여야 한다. 아래를 모든 화면 설계의 기본 요구로 삼는다.

- **실시간 소모 칼로리** — 세트를 마칠 때마다 누적 소모 칼로리가 즉시 올라가고, 홈 대시보드 에너지 링에 바로 반영된다. (체중 × MET × 시간으로 계산)
- **음식으로 환산해 체감시키기** — "약 180kcal"보다 "밥 반 공기만큼", "믹스커피 두 잔만큼"이 훨씬 와닿는다. 745종 음식 DB를 환산 기준으로 활용한다.
- **진척도 상시 표시** — "오늘 운동 3/8", "이 운동 2/3세트", 남은 예상 시간. 끝이 보여야 버틴다.
- **지난 기록 대비 성장** — "지난주보다 2회 더 하고 있어요", "이 운동 5번째예요". 초보자에게 가장 큰 동기는 자기 성장의 확인이다.
- **대안 운동의 효과 비교** — 운동을 바꿀 때 "이 운동은 원래 운동의 약 80% 효과, 무릎 부담은 절반" 식으로 보여준다. 바꾸는 것이 포기가 아니라 **현명한 선택**이 되게 한다.
- **누적 성과** — 세션 종료 시 이번 주 횟수·총 소모량, 연속 기록(스트릭)을 보여준다.

**수치 표현 원칙**: 칼로리·효과는 모두 추정치다. "182kcal"처럼 정밀하게 쓰지 말고 "약 180kcal"로 표기하며, 큰 숫자보다 **꾸준함**을 칭찬한다. 목표에 못 미쳐도 비난하지 않고 다음 행동을 제안한다(1단계에서 정한 톤 유지).

이 원칙은 운동에만 적용되지 않는다. 식단 기록, 야외 트래킹(3단계), 가족 공유(4단계)에도 동일하게 적용한다 — 걷는 중에도 거리·칼로리가 실시간으로 보이고, 가족에게는 수치 대신 꾸준함이 공유된다.

## 3. 요구사항 명세 (기능 목록)

### 3.1 온보딩 (첫 실행)
- 입력: 성별, 나이, 키, 체중, 평소 활동량, 목표(유지/증량/감량), 운동 경험(없음/조금/많음), 운동 가능 요일·시간, 장소(집/야외/헬스장), 알레르기·기피 음식
- 자동 계산: BMR → TDEE → 목표 칼로리, 탄단지 비율
- 결과: 개인 맞춤 주간 플랜(식단 방향 + 운동 스케줄) 자동 생성

### 3.2 식단 모듈
| 단위 | 기능 |
|------|------|
| 일 | 아침/점심/저녁/간식 기록, 음식 검색(식약처 영양 DB), 사진 기록, 칼로리·탄단지 자동 합산, 목표 대비 잔여 칼로리 표시 |
| 주 | 주간 식단표(계획 자동 제안 → 사용자가 수정), 장보기 목록 자동 생성, 계획 vs 실제 비교 |
| 월 | 월간 캘린더, 영양 균형 리포트(부족/과잉 영양소), 목표 달성률 |

- 목표별 식단 로직: 감량(-300~500kcal, 고단백), 유지(TDEE), 증량(+300~500kcal, 단백질 강화)
- 초보자 배려: 식단도 "이대로 드세요" 형태의 하루 식단 예시를 자동 제안 (직접 짜지 않아도 됨)

### 3.3 운동 모듈 — 실내 (홈트)
- **운동 라이브러리**: 부위별(전신/가슴/등/하체/코어/유산소/스트레칭) 40~60개 운동, 각 운동은 §2 원칙 2의 4단 설명 필수
- **오늘의 루틴 자동 배정**: 온보딩 결과 기반. 예) 감량+초보 → 주 3회, 회당 20분 서킷(스쿼트→푸시업(무릎)→플랭크→제자리 걷기)
- **운동 실행 화면**: 큰 동작 그림 + 핵심 자세 1줄 + 인터벌 타이머 + 음성/진동 안내 + "너무 힘들어요" 버튼(즉시 쉬운 변형으로 교체)
- **대안 교체 시스템(필수)**: 루틴 화면과 실행 화면 어디서든 "다른 운동으로 바꾸기" 가능. 운동 데이터에 대체 관계(같은 부위·같은 효과 그룹)를 미리 정의해 두고, 교체 사유(통증/장비 없음/소음/기타)를 선택하면 맞는 대안 2~3개 제시. 교체 이력은 학습되어 다음 자동 배정에 반영
- **단계적 성장**: 2~4주마다 난이도 자동 상향(횟수↑ → 세트↑ → 상위 동작)

### 3.4 운동 모듈 — 야외 (지도 트래킹)
- 걷기/러닝/자전거 모드, GPS 실시간 경로 표시(카카오맵 또는 Leaflet)
- 거리·시간·페이스·소모 칼로리 기록, 경로 히스토리 저장
- 초보자 가이드: 걷기→빨리 걷기→러닝 8주 프로그램(예: "1분 뛰고 2분 걷기 × 8회") 음성 안내

### 3.5 생활습관 모듈
- 체중·체지방 기록과 추이 그래프, 물 섭취, 수면 시간, 걸음 수, 습관 체크리스트

### 3.6 가족 공유 모듈 (배려 설계)
- **기본 공유**: 주간 식단표, 장보기 목록, "오늘 저녁 뭐 먹을까" 메뉴 투표
- **기본 비공개**: 체중, 체지방, 섭취 칼로리, 운동 기록 → 항목별 본인 선택 공개
- **응원**: 수치 없이 "오늘 목표 달성!" 배지만 공유, 이모지 응원
- **가족 식단 조율**: 같은 메뉴를 구성원 목표별로 양·구성만 다르게 표시(아빠 감량용 소량, 자녀 성장용 넉넉히)

### 3.7 리포트·대시보드
- 홈: 오늘의 잔여 칼로리, 오늘의 운동(시작 버튼), 물·걸음 위젯
- 리포트: 체중 추이, 주간 영양 균형, 운동 실적, 월간 요약

## 4. 운동 콘텐츠 확보 방안 (지식이 없어도 되는 이유)

운동 설명 콘텐츠는 다음 순서로 만듭니다. **발주자가 직접 운동 지식을 갖출 필요가 없습니다.**

1. **Claude가 초안 생성**: 운동별 4단 설명(방법·실수·호흡·변형)을 표준 운동 상식 기반으로 일괄 작성
2. **공신력 자료로 교차 확인**: 국민체력100(국민체육진흥공단), 보건소 건강 자료 등 공공 가이드와 대조
3. **그림 확보**: ① 무료 운동 일러스트/GIF 라이브러리 활용, ② SVG 스틱맨 애니메이션을 코드로 직접 생성(저작권 문제 없음, 추천), ③ 유튜브 공식 채널 링크 첨부(보조)
4. **면책 문구**: "본 앱의 운동·식단 정보는 일반 가이드이며 의료 조언이 아닙니다. 통증이 있으면 중단하고 전문가와 상담하세요."를 앱 내 명시

## 5. 화면 구조 (사이트맵)

```
홈 대시보드
├─ 식단 (일/주/월 탭)
│   ├─ 오늘 기록 · 음식 검색 · 사진
│   ├─ 주간 식단표 · 장보기 목록
│   └─ 월간 리포트
├─ 운동
│   ├─ 오늘의 루틴 (자동 배정 → 실행 화면)
│   ├─ 야외 트래킹 (지도)
│   └─ 운동 라이브러리 (검색·부위별 → 상세 4단 설명)
├─ 습관 (체중·물·수면·걸음)
├─ 리포트 (그래프 종합)
├─ 가족 (식단표 공유·투표·응원)
└─ 설정 (목표·공개범위·알림)
```

## 7. 완성까지 로드맵

| 단계 | 내용 | 산출물 | 예상 기간 |

## 8. Claude에게 작업 지시하는 방법

새 대화에서 작업할 때는 이 문서를 첨부하고 아래처럼 지시하면 됩니다.

> "첨부한 마스터 문서 기준으로 2단계(실내 운동) 중 운동 라이브러리부터 만들어줘. 하체 운동 10개의 4단 설명과 SVG 애니메이션을 포함해서."

지시 원칙:
- 한 번에 한 단계(또는 그 일부)씩 요청
- 결과물 확인 후 수정 요청 → 확정 → 다음 진행
- 문서와 다르게 진행하고 싶으면 이 문서를 먼저 수정

## 9. 유의사항

- 운동·식단 정보는 일반 가이드로 제공하며 의료 조언이 아님을 앱과 문서에 명시
- 민감정보(체중 등)는 기본 비공개, 공유는 항목별 옵트인
- GPS 트래킹은 위치 갱신 주기(3~5초)로 배터리 소모 최소화, 통신 불가 지역 대비 로컬 우선 저장
- 운동 그림·설명 콘텐츠는 저작권 안전한 자체 제작(SVG) 또는 공공 자료 기반
